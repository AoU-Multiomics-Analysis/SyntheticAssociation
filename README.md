# SyntheticAssociation

## Overview
This pipeline detects synthetic associations in QTL fine-mapping results. It takes fine-mapping results produced at two different minor allele frequency (MAF) thresholds — typically MAF > 1% (common variants) and MAF > 0.1% or lower (rare variants) — and identifies variants that appear uniquely in each analysis.

Using these distinct variant sets, the pipeline performs conditional regression analysis: it tests whether a rare variant's association signal persists or disappears after conditioning on a common variant in the same credible set, and vice versa. A rare variant that loses its signal when conditioned on a common variant is a candidate **synthetic association** — a situation where the apparent effect of the rare variant is actually driven by linkage disequilibrium (LD) with a common causal variant.

---

## Scripts

### `scripts/SyntheticAssociations.R`

The core analysis script. It:

1. **Parses inputs** – reads in the genotype dosage matrix, QTL covariates, thresholded fine-mapping parquet file, full fine-mapping TSV, and the phenotype BED file.
2. **Identifies variant sets** – for each gene, it finds rare variants (MAF < 1%, PIP > 0.9) present only in the full fine-mapping analysis and the lead common variants from each credible set in the thresholded analysis.
3. **Extracts genotype data** – uses tabix-indexed genotype dosage files to pull dosages for the relevant variants.
4. **Runs conditional regression** – for each pair of rare and common variants, fits a linear model of the phenotype on both variants jointly (conditional) and on each variant alone (marginal), including QTL covariates.
5. **Computes LD** – calculates the correlation between each variant pair.
6. **Writes results** – outputs a TSV file with conditional and marginal regression statistics (estimate, standard error, p-value) along with the LD between variant pairs.

**Command-line arguments:**

| Argument | Description |
|---|---|
| `--genotype_matrix` | Path to genotype dosage matrix (tabix-indexed, from BCFtools) |
| `--covariates` | Path to QTL covariates file in QTLtools format |
| `--out_prefix` | Prefix for output files |
| `--thresholded_finemapping` | Path to Parquet file for fine-mapping run at a higher MAF threshold |
| `--full_finemapping` | Path to TSV file for fine-mapping run across all variants (with annotated allele frequencies) |
| `--phenotype_bed` | Path to BED file containing molecular phenotype data (same format as tensorQTL input) |

## Workflows

### `workflows/SyntheticAssociations.wdl`

A WDL (Workflow Description Language) workflow that wraps the R script for execution on cloud platforms (e.g., Terra/Cromwell). It defines a single task, `ConditionalRegression`, and a top-level workflow, `SyntheticAssociations`.

#### Task: `ConditionalRegression`

Runs inside the `ghcr.io/aou-multiomics-analysis/syntheticassociation:main` Docker container. Before calling the R script, the task filters the phenotype BED file to include only the gene specified by `OutputPrefix`, then invokes `SyntheticAssociations.R` with the provided inputs.

#### Workflow: `SyntheticAssociations`

Calls the `ConditionalRegression` task and surfaces its output.

**Inputs:**

| Input | Type | Description |
|---|---|---|
| `GenotypeMatrix` | File | Tabix-indexed genotype dosage matrix for the cis window (generated by the susieR workflow) |
| `GenotypeMatrixIndex` | File | Index file for `GenotypeMatrix` |
| `QTLCovariates` | File | Covariates file used in tensorQTL and SuSiE |
| `OutputPrefix` | String | Gene ID used as output prefix and to filter the phenotype BED file |
| `ThresholdFinemapping` | File | Parquet file for fine-mapping run at a higher MAF threshold |
| `FullFinemapping` | File | TSV file with annotated allele frequencies for all variants (standard fine-mapping output) |
| `PhenotypeBed` | File | BED file of molecular phenotype data (same format as tensorQTL input) |
| `Memory` | Int | Memory in GB to allocate to the task |
| `NumPrempt` | Int | Number of preemptible attempts |

**Outputs:**

| Output | Type | Description |
|---|---|---|
| `ConditionalRes` | File | TSV file with conditional and marginal regression results (`<OutputPrefix>_conditional_analysis.tsv`) |

## GitHub Actions Workflows

### `.github/workflows/docker-image.yml` — Docker Image CI

Triggered on every push to the `main` branch. This workflow:

1. Checks out the repository.
2. Logs in to the GitHub Container Registry (`ghcr.io`) using the `GITHUB_TOKEN`.
3. Extracts Docker image metadata (tags and labels) based on the Git ref.
4. Builds the Docker image from `envs/Dockerfile` and pushes it to `ghcr.io/aou-multiomics-analysis/syntheticassociation`.

The resulting image is tagged with the branch name (e.g., `main`) and is used as the runtime environment in the WDL workflow.

---

## Docker Environment

The Docker image is defined in `envs/Dockerfile`. It is built on top of `mambaorg/micromamba` and installs the following R packages via conda/mamba:

- `r-tidyverse`, `r-data.table`, `r-magrittr`, `r-optparse`, `r-janitor`
- `r-devtools`, `r-remotes`, `r-arrow`
- `bioconductor-genomicranges`, `bioconductor-rsamtools`, `bioconductor-summarizedexperiment`
- [`eQTLUtils`](https://github.com/kauralasoo/eQTLUtils) (installed from GitHub)

The `SyntheticAssociations.R` script is copied into the container at build time.
